[GitHub Copilot CLI][about-copilot-cli] は、ターミナルで動作する強力なエージェント型コーディング アシスタントです。コードベースを調べ、コードを生成し、コマンドを実行し、外部ツールを利用できます。タスクを任せたり、変更を依頼したりしながら、コマンド ラインで作業に集中できます。まず Copilot CLI をインストールします。使い慣れているツールでインストールできます。

このレッスンでは、次のことを行います。

- npm で GitHub Copilot CLI をインストールします。
- GitHub アカウントで認証します。
- ワークショップのリポジトリを信頼し、簡単な会話を試します。
- 組み込みの GitHub Model Context Protocol (MCP) サーバーでフィルタリングの Issue を見つけます。

## シナリオ

チームは増え続けるバックログに対応するため、人工知能 (AI) エージェントを使い始めています。Copilot CLI は、開発者が日常的に使うターミナルでその機能を利用できるようにします。このレッスンでは、残りのワークショップで使えるようにインストールと認証を済ませます。

## Copilot CLI をインストールする

Copilot CLI は [npm][install-cli]、WinGet、Homebrew でインストールできます。GitHub Codespaces には Node.js があらかじめインストールされているため、ここでは npm を使います。

1. Codespace に戻り、ターミナルを開きます。
2. Node.js がインストールされ、必要なバージョンを満たしていることを確認します。

   ```bash
   node --version
   ```

   バージョン 24 以上が表示されます。

3. Copilot CLI をグローバルにインストールします。

   ```bash
   npm install -g @github/copilot
   ```

4. インストールを確認します。

   ```bash
   copilot --version
   ```

   バージョン番号が表示されます。

## GitHub で認証する

初回起動時に、Copilot CLI は GitHub アカウントでの認証を求めます。

1. Copilot CLI を起動します。

   ```bash
   copilot
   ```

2. 認証を求められた場合は、デバイス コードの手順に従って認証し、Copilot CLI を承認します。
3. Copilot CLI に次のプロンプトが表示されることを確認します。

   ```plaintext
   Copilot can read files in this folder and, with your permission, edit them or run code and shell commands. It will remember your permissions for the rest of this session.

   Do you trust the files in this folder?
   ```

4. 表示されたパスが Tailspin Toys リポジトリであることを確認し、**Yes, and remember this folder for future sessions** を選択します。

> [!NOTE]
> Codespace では、GitHub セッションを通じてすでに認証されている場合があります。認証を求められずに Copilot CLI が起動した場合は、そのまま進めてください。

## 基本操作を確認する

通常のシェル プロンプトでは、コマンドは Codespace で直接実行されます。Copilot CLI を起動すると、自然な言葉でエージェントに指示し、スラッシュ コマンドで会話を操作できます。

1. `/model` を入力し、矢印キーで **Auto** を選択して <kbd>Enter</kbd> を押し、もう一度 <kbd>Enter</kbd> を押して確定します。
2. `/help` を入力して、インストール済みバージョンで利用できるコマンドを確認し、<kbd>Esc</kbd> でヘルプ画面を閉じます。
3. 次の質問を送信し、Copilot が正しく動作することを確認します。

   ```plaintext
   What are the key files in this project?
   ```

4. 回答を読み、Copilot が答える前にリポジトリを調べることを確認します。
5. `/mcp list` を入力し、組み込みの GitHub MCP サーバーが利用できることを確認します。
6. 次のプロンプトでフィルタリングの Issue を探します。

   ```plaintext
   Using GitHub MCP, find the issue in this repository titled "Allow users to filter games by category and publisher." Give me its URL and a short summary. Don't change anything.
   ```

7. 表示された URL を開いて Issue を読みます。最初の小さな変更を終えた後に、この Issue を使います。

> [!TIP]
> 通常の Copilot CLI セッションは、ターミナルで現在チェックアウトされているブランチを使い、自動では worktree を作成しません。変更ごとに機能ブランチを作成します。

## ワークショップ用のショートカットを使う

通常 Copilot CLI は、設定済みの許可範囲外のツールを使う前に確認を求めます。このワークショップでは、ユーザーが許可したショートカット `--yolo` を使って Codespace 内で再起動し、承認プロンプトを省略して演習に集中します。

> [!CAUTION]
> `--yolo` は、すべてのツール、パス、Uniform Resource Locator (URL) に対する自動許可 (`--allow-all-tools`、`--allow-all-paths`、`--allow-all-urls`) を有効にします。Codespace や仮想マシン (VM) などの隔離された環境でのみ使い、日常の開発で既定値としてエイリアスにしないでください。詳細は[ツールの使用を許可または禁止する][allow-all-warning]を参照してください。

`--enable-all-github-mcp-tools` は、このワークショップの後続レッスンで Issue やプルリクエストを操作するための、読み取りと書き込みの GitHub MCP ツールを有効にします。Codespace によりローカル コンピューターへのアクセスは制限されますが、認証済みの GitHub リソースは実際のものです。公開やマージの前に変更をレビューしてください。

1. `/exit` で Copilot CLI を終了します。
2. リポジトリのルートから再起動します。

   ```bash
   copilot --yolo --enable-all-github-mcp-tools
   ```

3. プロジェクトについて簡単な質問を送り、会話が動作することを確認してから `/exit` で終了します。

Copilot は会話を自動保存します。後で指示を変更したりエージェントを追加したりした後、`copilot --resume` で同じ会話とブランチに戻ります。

- npm を使って GitHub Copilot CLI をインストールしました。
- GitHub アカウントで認証しました。
